- `run_g0.py`：顺序执行测试、环境、真实数据目录清单和自拟样例读取，记录命令、退出码、依赖、输入/代码哈希及缺项；发现缺失的真实数据/模型验证时返回2。
- 项目级环境与带哈希依赖锁；原始数据、模型、运行记录、环境和复现清单不进入Git。

词法规范化只用于提示重复候选，不能代替完整近重复检测或实体/事件分组。`case_id`是自拟样例作者明确提供的测试字段，不是官方字段。当前未实施实体归并、时间线、推理或正式评分器。

## 复现入口

当前锁针对Windows x86_64、CPython3.11、CUDA12.8版PyTorch；不是最终比赛部署锁。依据[PyTorch官方版本表](https://pytorch.org/get-started/previous-versions/)选择2.9.1+cu128，不因最新版变化自动升级。完整模型栈待指定模型确认后单独验证。

从项目根目录运行：

```powershell
& .\scripts\setup_g0.ps1
.\.venv\Scripts\python.exe scripts/run_g0.py --run-id g0-NEW-UNIQUE-NAME
```

每次必须使用新的run-id；已有目录和报告拒绝覆盖。`runs/<run-id>/g0_status.json`是该次运行的权威记录，旁边保留子命令日志及报告。返回0用于单项工具检查成功；总检查返回2表示外部前提仍缺少，不能解释为G0全部通过。失败返回1。

领取真实数据后，先将原件放入`data/raw`，保留压缩包及解压版本哈希；确认官方格式后再显式传字段：

```powershell
.\.venv\Scripts\python.exe scripts/d01.py audit --input data/raw/ACTUAL_FILE.jsonl --id-field ACTUAL_ID_FIELD --text-field ACTUAL_TEXT_FIELD --output runs/NEW_RUN/official-data-audit.json
```

上例的大写参数是占位说明，不能直接当作真实输入。若JSON根对象包含数组，使用`--records-key`；业务组须经实际数据审计确定后传入`--group-field`。本工具只证明读取和基础结构，不证明标注正确、无语义泄漏或满足官方完整schema。
